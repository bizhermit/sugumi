# DB バックアップ

[目次](index.md)

DB のデータのバックアップを取り、復元する。対象は、DB ユーザー `migrator` が持つすべてのスキーマ（テーブル・ビュー・関数・権限を含む）。
アプリのコード・`.env`・ログ・証明書は含まない。

DB コンテナの `db-backup` でバックアップを取り、`db-restore` で復元する。
どちらもファイルは扱わず、標準出力に書き出し、標準入力から読む。ファイルは、ホストで運用者の権限で扱う。

コマンドは、DB サーバーの `/opt/myapp-db` で実行する。
例では、バックアップを DB サーバーの `/var/backups/myapp` に置く（「[DB サーバーの構築方法](db-server.md#db-サーバーの構築方法)」の手順の 7 で作成する）。

## DB バックアップの取得方法

```sh
docker compose --env-file .env exec -T db db-backup > "/var/backups/myapp/$(date -u +%Y%m%dT%H%M%SZ).dump"
```

- アプリを動かしたまま取れる。取り始めた時点の、そろった状態が書き出される。
- ファイル名には、取った日時（UTC）が入る。名前順が、取った順になる。
- `-T` を付ける。付けないと、端末を通るときに中身が書き換わり、復元できないファイルになる。
- エラーが出たときは、できたファイルを削除する。途中までしか書かれていない。
- バックアップには、パスワードのハッシュ・セッション・アプリの鍵（`secrets` テーブル）が入る。
  DB と同じように扱い、ほかの人が読み書きできない場所に置く。
- サーバーが壊れたときに備え、別のサーバーやストレージにも写す。写すときは暗号化する。

確認方法：エラーが出ず、「[DB バックアップ一覧の確認方法](#db-バックアップ一覧の確認方法)」で、取ったファイルの大きさが 0 でない。

## DB バックアップからの復元方法

`migrator` が持つスキーマをすべて削除し、バックアップの内容で再作成する。今のデータは消えるので、必要なら先にバックアップを取る。

1. すべてのアプリサーバーで、アプリを止める。DB のテーブルを置き換えた後に、再起動する必要があるため。
   新しいサーバーに復元するときは、先に「[本番環境の構築方法](setup.md)」で起動してから止める。

   ```sh
   docker compose --env-file docker/.env stop app
   ```

   - 止まるのはアプリのコンテナ（`app`）だけ。
   - `stop` で止めたコンテナは、手順の 3 で `start` するまで、自動では起動しない。

2. DB サーバーで、復元する。

   ```sh
   docker compose --env-file .env exec -T db db-restore < /var/backups/myapp/20261027T030000Z.dump
   ```

   - 1 つのトランザクションで実行する。失敗したときや中断したときは、元のデータのまま残る。
     - 書き換えられたバックアップでは、そうとは限らない。そのときは、別のバックアップから復元し直す。
     - バックアップを読み終えた後は、Ctrl-C を押しても、コンテナの中では最後まで進む。
   - どれかのアプリサーバーから接続が残っていると、失敗する。
     接続を閉じた後の止め忘れは分からないので、復元の前に必ずすべてのアプリを止める。
   - アプリのテーブルがないバックアップ（マイグレーションの前に取ったものなど）は、復元しない。
   - スキーマを持つ DB ユーザー `migrator` で実行する。管理者では実行しない。
     バックアップの中の関数が、データを入れるときに管理者の権限で動くため。手で `pg_restore` などを管理者で実行しない。

3. すべてのアプリサーバーで、アプリを起動する。

   ```sh
   docker compose --env-file docker/.env start app
   ```

- アプリは、バックアップを取ったときと同じバージョンのイメージで起動する。
  新しいバージョンで起動するときは、先にマイグレーションを実行する（「[アプリの更新方法](update.md)」の手順の 4）。
- バックアップを取った後のログアウト・パスワードの変更・アカウントの削除やロックも、取り消される。
- DB ユーザー（`app`・`migrator`）とパスワードは、バックアップに含まない。復元先の DB の初期化で、DB サーバーの `.env` の値から作成される。

確認方法：手順の 2 でエラーが出ず、アプリを起動した後にログインできる。

## DB バックアップ一覧の確認方法

```sh
ls -l /var/backups/myapp
```

## DB バックアップの削除方法

```sh
rm /var/backups/myapp/20261027T030000Z.dump
```
