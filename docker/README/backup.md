# DB バックアップ

[目次](index.md)

DB のバックアップを取り、復元する。対象は DB 全体で、データ・DB スキーマ・DB ユーザー・パスワード・設定がすべて入る。
アプリのコード・`.env`・ログ・証明書は含まない。

DB コンテナの `db-backup` でバックアップを取り、`db-restore` で復元する。
どちらもファイルは扱わず、標準出力に書き出し、標準入力から読む。ファイルは、ホストで運用者の権限で扱う。

コマンドは、DB サーバーの `/opt/myapp-db` で実行する。
例では、バックアップを DB サーバーの `/var/backups/myapp` に置く（「[DB サーバーの構築方法](db-server.md#db-サーバーの構築方法)」の手順の 7 で作成する）。

## DB バックアップの取得方法

```sh
docker compose --env-file .env exec -T db db-backup > "/var/backups/myapp/$(date -u +%Y%m%dT%H%M%SZ).tar.gz"
```

- アプリを動かしたまま取れる。取り終えた時点の、そろった状態が書き出される。
- ファイル名には、取った日時（UTC）が入る。名前順が、取った順になる。
- `-T` を付ける。付けないと、端末を通るときに中身が書き換わり、復元できないファイルになる。
- エラーが出たときは、できたファイルを削除する。途中までしか書かれていない。
  - 書き込みが多いときは、`could not read WAL` などのエラーで失敗することがある。そのときは取り直す。
- バックアップには、パスワードのハッシュ・セッション・アプリの鍵（`secrets` テーブル）が入る。
  DB と同じように扱い、ほかの人が読み書きできない場所に置く。
- サーバーが壊れたときに備え、別のサーバーやストレージにも写す。写すときは暗号化する。

確認方法：エラーが出ず、「[DB バックアップ一覧の確認方法](#db-バックアップ一覧の確認方法)」で、取ったファイルの大きさが 0 でない。

## DB バックアップからの復元方法

DB のデータのディレクトリを、バックアップの内容で置き換える。今のデータは消えるので、必要なら先にバックアップを取る。

前提条件：DB サーバーのイメージの PostgreSQL のメジャーバージョンが、バックアップを取ったときと同じ。

1. すべてのアプリサーバーで、アプリを止める。

   ```sh
   docker compose --env-file docker/.env stop app
   ```

   - 止まるのはアプリのコンテナ（`app`）だけ。
   - `stop` で止めたコンテナは、手順の 5 で `start` するまで、自動では起動しない。

2. DB サーバーで、DB を止める。新しいサーバーに復元するときは、先に「[DB サーバーの構築方法](db-server.md#db-サーバーの構築方法)」で起動してから止める。

   ```sh
   docker compose --env-file .env stop db
   ```

3. DB サーバーで、復元する。DB のコンテナとは別に、一時的なコンテナを起動して実行する。

   ```sh
   docker compose --env-file .env run --rm -T db db-restore < /var/backups/myapp/20261027T030000Z.tar.gz
   ```

   - バックアップをすべて読み、壊れていないことを確かめてから置き換える。失敗したときや中断したときは、元のデータのまま残る。
   - 書き換えられたバックアップは、壊れていないものとして復元される。見分けられない。
   - DB が動いていると、何もせずに失敗する。
   - 置き換えるまでの間、バックアップを展開する分の空き容量が、データのボリュームに要る。

4. DB サーバーで、DB を起動する。

   ```sh
   docker compose --env-file .env start db
   ```

5. すべてのアプリサーバーで、アプリを起動する。

   ```sh
   docker compose --env-file docker/.env start app
   ```

- アプリは、バックアップを取ったときと同じバージョンのイメージで起動する。
  新しいバージョンで起動するときは、先にマイグレーションを実行する（「[アプリの更新方法](update.md)」の手順の 3）。
- バックアップを取った後のログアウト・パスワードの変更・アカウントの削除やロックも、取り消される。
- DB ユーザーのパスワードも、バックアップを取ったときのものに戻る。
  バックアップを取った後に DB パスワードを変更していたら、もう一度変更する（「[DB パスワードの変更方法](db-server.md#db-パスワードの変更方法)」）。
  新しいサーバーに復元したときも、そのサーバーの `.env` の値ではなく、バックアップのパスワードになる。

確認方法：手順の 3 でエラーが出ず、アプリを起動した後にログインできる。

## DB バックアップ一覧の確認方法

```sh
ls -l /var/backups/myapp
```

## DB バックアップの削除方法

```sh
rm /var/backups/myapp/20261027T030000Z.tar.gz
```
