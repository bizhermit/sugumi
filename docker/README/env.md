# 環境変数

[目次](index.md)

各サーバーの `.env` に書く値の一覧。変更したら、そのサーバーで `docker compose --env-file <.env のパス> up -d` を実行して再起動する。

- 値は単一引用符で囲む。囲まないと `$` が変数として展開される。値に `'` は使えない。
- 「必須」の値を空のままにすると起動しない。
- `IMAGE_PREFIX`・`IMAGE_TAG` は、どのサーバーも同じ値にする。

## アプリサーバー（docker/.env）

| 名前                                                                                                           | 必須 | 内容                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `IMAGE_PREFIX`                                                                                                 | ○    | イメージの保存先。レジストリとアプリの名前（例：`123456789012.dkr.ecr.ap-northeast-1.amazonaws.com/myapp`）。「[イメージのビルド方法](build.md)」で指定したもの |
| `IMAGE_TAG`                                                                                                    | ○    | 起動するイメージのタグ。「[イメージのビルド方法](build.md)」で付けたもの                                                                                        |
| `APP_MODE`                                                                                                     |      | アプリのモード。本番では書かないか `PROD` にする（`DEV`・`MOCK` にしない）                                                                                      |
| `TRUSTED_PROXIES`                                                                                              |      | アプリから見たロードバランサーのアドレス。「[接続元 IP アドレスの受け渡し](load-balancer.md#接続元-ip-アドレスの受け渡し)」を参照                               |
| `REQUEST_BODY_TIMEOUT_SECONDS`・`DB_POOL_MAX`・`DB_CONNECTION_TIMEOUT_SECONDS`・`DB_STATEMENT_TIMEOUT_SECONDS` |      | リクエストボディの読み込みと DB の時間制限、DB の接続数。「[アプリの時間制限](#アプリの時間制限)」を参照                                                        |
| `SESSION_IDLE_TIMEOUT_MINUTES` ほか                                                                            |      | セッションの期限、ログイン制限、ログイン前 CSRF トークンの期限。「[セッションとログインの制限](#セッションとログインの制限)」を参照                             |
| `DB_HOST`                                                                                                      | ○    | DB サーバーの名前か IP アドレス。DB 証明書の名前と揃える（「[証明書の作成方法](db-server.md#証明書の作成方法)」）                                               |
| `DB_APP_PASSWORD`                                                                                              | ○    | アプリが DB に接続するときの DB ユーザー `app` のパスワード。DB サーバーの `DB_APP_PASSWORD` と同じ値                                                           |
| `LOG_DESTINATION` ほか                                                                                         | ○    | ログ送信先。「[ログ送信先の設定値](#ログ送信先の設定値)」を参照                                                                                                 |
| `APP_LISTEN_ADDRESS`                                                                                           |      | アプリが待ち受けるこのサーバーのアドレス（`127.0.0.1`）。ロードバランサーが別のサーバーにあるなら、そこから届くアドレスにする                                   |
| `APP_NETWORK_SUBNET`                                                                                           | ○    | アプリのコンテナを置くネットワークの範囲（例：`172.30.255.0/24`）。「[ネットワーク範囲の決め方](#ネットワーク範囲の決め方)」を参照                              |
| `APP_NETWORK_GATEWAY`                                                                                          | ○    | そのネットワークのゲートウェイ。ふつうは範囲の最初のアドレス（例：`172.30.255.1`）                                                                              |

## DB サーバー（.env）

| 名前                        | 必須 | 内容                                                                                                          |
| --------------------------- | ---- | ------------------------------------------------------------------------------------------------------------- |
| `IMAGE_PREFIX`・`IMAGE_TAG` | ○    | アプリサーバーと同じ                                                                                          |
| `DB_ADMIN_PASSWORD`         | ○    | DB の管理者のパスワード                                                                                       |
| `DB_APP_PASSWORD`           | ○    | DB ユーザー `app` のパスワード。初期化のときに使う                                                            |
| `DB_LISTEN_ADDRESS`         | ○    | `db-proxy` が待ち受けるこのサーバーのアドレス。アプリサーバーから届くアドレスにする（`127.0.0.1` にはしない） |

## ロードバランサー（.env）

| 名前                        | 必須 | 内容                                                                                                                                   |
| --------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `IMAGE_PREFIX`・`IMAGE_TAG` | ○    | アプリサーバーと同じ                                                                                                                   |
| `LB_SERVER_NAME`            | ○    | 受け付けるホスト名（例：`example.com`）。空白で区切って複数書ける。「[受け付けるホスト名](load-balancer.md#受け付けるホスト名)」を参照 |

振り分け先と証明書は、`.env` ではなくファイルで置く（「[ロードバランサーの構築方法](load-balancer.md#ロードバランサーの構築方法)」）。

## ネットワーク範囲の決め方

`APP_NETWORK_SUBNET`・`APP_NETWORK_GATEWAY` の決め方。

- サーバーのほかのネットワーク（ほかの Docker のネットワーク、LAN、VPN）と重ならない範囲を選ぶ。
  - 使われている範囲は、`ip route` や `docker network inspect` で確認する。
  - 重なると、起動時に `Pool overlaps` のエラーになる。
- 同じサーバーのロードバランサーから `127.0.0.1:3000`
  へ転送すると、アプリにはゲートウェイのアドレスから接続したように見える。
  - ネットワークを再作成するたびにこのアドレスが変わらないよう、固定している。

## アプリの時間制限

アプリは、リクエストボディの読み込みと DB の待ちを、次の値で打ち切る。書かなければ、デフォルト値（[src/lib/env.ts](../../src/lib/env.ts)）を使う。

| 名前                            | 内容                                                                    |
| ------------------------------- | ----------------------------------------------------------------------- |
| `REQUEST_BODY_TIMEOUT_SECONDS`  | リクエストボディを読み終えるまでの秒数。過ぎたら 408 を返す             |
| `DB_POOL_MAX`                   | 1 つのアプリのインスタンスが開く DB の接続の数                          |
| `DB_CONNECTION_TIMEOUT_SECONDS` | DB の接続の空きを待つ秒数。過ぎたら 503 を返す                          |
| `DB_STATEMENT_TIMEOUT_SECONDS`  | 1 つの SQL の文にかけてよい秒数。過ぎたら DB が文を取り消し、503 を返す |

- `DB_POOL_MAX` にアプリサーバーの数を掛けた数は、PostgreSQL の `max_connections` より少なくする。
  - 管理者で `psql` から接続する分の余裕を残す。
- マイグレーション（`db-migrate`）には、`DB_STATEMENT_TIMEOUT_SECONDS` をかけない。
- リクエストボディのタイムアウトは、1 回の読み込みではなくボディ全体にかかる。遅い回線で 1 MB 近くを送るユーザーがいるなら、長くする。
- ロードバランサーのタイムアウトも合わせて見直す（「[タイムアウト](load-balancer.md#タイムアウト)」）。

## セッションとログインの制限

書かなければ、デフォルト値（[src/lib/env.ts](../../src/lib/env.ts)）を使う。

| 名前                               | 内容                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| `SESSION_IDLE_TIMEOUT_MINUTES`     | 操作がないまま、セッションが切れるまでの分数。0 なら切れない                                 |
| `SESSION_ABSOLUTE_TIMEOUT_MINUTES` | 操作を続けていても、ログインからセッションが切れるまでの分数。0 なら切れない                 |
| `LOGIN_MAX_FAILED_ATTEMPTS`        | アカウントをロックするまでの、続けて失敗した回数。0 ならロックしない                         |
| `LOGIN_LOCKOUT_MINUTES`            | ロックしたアカウントを自動で解除するまでの分数                                               |
| `LOGIN_DEVICE_DAYS`                | ログインに成功した端末を覚えておく日数。覚えている端末は、ロックと接続元ごとの制限を受けない |
| `LOGIN_IP_MAX_FAILED_ATTEMPTS`     | 同じ接続元からのログインを受け付けなくなるまでの、失敗の回数。0 なら制限しない               |
| `LOGIN_IP_WINDOW_MINUTES`          | `LOGIN_IP_MAX_FAILED_ATTEMPTS` の回数を数える期間の分数                                      |
| `LOGIN_IP_LOCKOUT_MINUTES`         | 制限を超えた接続元からのログインを受け付けない分数                                           |
| `PRE_LOGIN_CSRF_TIMEOUT_MINUTES`   | ログイン前に表示したフォームの CSRF トークンが有効な分数。0 なら切れない                     |

## ログ送信先の設定値

使い方は「[ログ送信先の設定方法](logs.md#ログ送信先の設定方法)」を参照。

| 名前                    | 必須 | 内容                                                       |
| ----------------------- | ---- | ---------------------------------------------------------- |
| `LOG_DESTINATION`       | ○    | `cloudwatch` か `internal`                                 |
| `SERVER_NAME`           | ○    | このサーバーの名前（例：`app-1`）。ログの `server` に入る  |
| `LOG_BUFFER_MAX_SIZE`   |      | 送れない間にためる量の上限（`5G`）                         |
| `AWS_REGION`            |      | `cloudwatch`：送信先のリージョン（例：`ap-northeast-1`）   |
| `CLOUDWATCH_LOG_GROUP`  |      | `cloudwatch`：ロググループの名前。先に作成しておく         |
| `LOG_SERVER_HOST`       |      | `internal`：ログ用サーバーのホスト名。証明書の名前と揃える |
| `LOG_SERVER_PORT`       |      | `internal`：ログ用サーバーのポート（`24224`）              |
| `LOG_SERVER_SHARED_KEY` |      | `internal`：ログ用サーバーと揃える共有鍵                   |
