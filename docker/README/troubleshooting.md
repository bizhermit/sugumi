# トラブルシューティング

[目次](index.md)

## ユーザーがログインできない

原因：ログイン失敗が続き、接続元ごとの制限かアカウントロックがかかっている。

解決：監査ログで、そのユーザーの `address_blocked`（接続元ごとの制限）か `account_locked`（アカウントロック）を探す（「[ログの調査方法](logs.md#ログの調査方法)」）。

- `address_blocked` なら、「[接続元ごとの制限の解除方法](login-limits.md#接続元ごとの制限の解除方法)」。
- `account_locked` なら、「[アカウントロックの解除方法](login-limits.md#アカウントロックの解除方法)」。

## 全員がしばらくログインできなくなる

原因：アプリが接続元 IP アドレスを取れず、全員の接続元がロードバランサーのアドレスになっている。
誰かがログインに失敗を重ねると、全員に接続元ごとの制限がかかる。

解決：「[接続元 IP アドレスの受け渡し](load-balancer.md#接続元-ip-アドレスの受け渡し)」の設定を行い、その確認方法で確認する。

## ロードバランサーが 502 を返す

原因：振り分け先のアプリサーバーに、どれも接続できない。

解決：

- 各アプリサーバーで、`app` が動いているか確認する（「[アプリが再起動を繰り返す](#アプリが再起動を繰り返す)」）。
- ロードバランサーの `upstream/servers.conf` のアドレスが、アプリサーバーの `APP_LISTEN_ADDRESS` と合っているか確認する（「[振り分け先の変更方法](load-balancer.md#振り分け先の変更方法)」）。
- アプリサーバーのファイアウォールで、ロードバランサーからの接続を止めていないか確認する。

## ロードバランサーが 504 を返す

原因：nginx の `proxy_read_timeout` が、アプリが DB を待つ時間より短い。アプリが 503 を返す前に、nginx が打ち切っている。

解決：[docker/lb/nginx.conf](../lb/nginx.conf) の `proxy_read_timeout` を、`DB_CONNECTION_TIMEOUT_SECONDS` と `DB_STATEMENT_TIMEOUT_SECONDS` の合計より十分に長くする（「[タイムアウト](load-balancer.md#タイムアウト)」）。

## アプリが再起動を繰り返す

原因：アプリは起動時に DB に接続し、DB スキーマのバージョンが自身と同じかを確認する。接続できないか、バージョンが違うと終了する。

解決：アプリサーバーで `docker compose --env-file docker/.env logs app` のエラーを見る。

- 証明書のエラー（`unable to verify the first certificate` など）：`docker/certs/db-ca.crt` が、DB 証明書を発行した CA のものか確認する。
  証明書の名前のエラーなら、`DB_HOST` が DB 証明書の名前（`subjectAltName`）と同じか確認する（「[証明書の作成方法](db-server.md#証明書の作成方法)」）。
- 接続できない・時間切れ：DB サーバーの `DB_LISTEN_ADDRESS` と、DB サーバーのファイアウォール（アプリサーバーから 5432 に届くか）を確認する。
- パスワードのエラー：アプリサーバーの `DB_APP_PASSWORD` が、DB に設定したパスワードと同じか確認する（「[DB パスワードの変更方法](db-server.md#db-パスワードの変更方法)」）。
- `DB のスキーマのバージョンがアプリと合いません` のエラー：
  - DB のほうが古い（`DB 4、アプリ 5` など）なら、マイグレーションを実行していない。「[マイグレーションの実行方法](migration.md#マイグレーションの実行方法)」を行う。
  - DB のほうが新しいなら、アプリのイメージが古い。`IMAGE_TAG` を、マイグレーションを実行したときのタグに揃える。

## マイグレーションに失敗した

原因：`db-migrate` がエラーで終わった。1 つのトランザクションで適用するので、DB スキーマは元のまま残っている。

解決：エラーを見て、原因を取り除く。

- `DB のスキーマのほうが新しいです`：DB サーバーの `IMAGE_TAG` が、前に適用したときより古い。新しいイメージのタグにして起動し直してから実行する。
- `マイグレーションのファイル名は…`・`マイグレーションの番号が続いていません`：[docker/db/migrations/](../db/migrations/) のファイル名の誤り。直したイメージをビルドする。
- SQL のエラー（`適用します: 0005_….sql` の後の `ERROR: …`）：そのマイグレーションの誤り。直したイメージをビルドするまでは、DB サーバーとすべてのアプリサーバーの `IMAGE_TAG` を元のタグに戻して起動する。
  `EXECUTE of transaction commands is not implemented` なら、マイグレーションに `COMMIT`・`ROLLBACK` などが入っている。マイグレーションには書けない。

## 起動時に `Pool overlaps` のエラーになる

原因：`APP_NETWORK_SUBNET` の範囲が、サーバーのほかのネットワークと重なっている。

解決：重ならない範囲を選び直す（「[ネットワーク範囲の決め方](env.md#ネットワーク範囲の決め方)」）。

## 起動時に `.env に … を書いてください` のエラーになる

原因：`.env`（アプリサーバーは `docker/.env`）に必須の値がないか、`--env-file` を付け忘れている。

解決：値を書き（「[環境変数](env.md)」）、`--env-file` を付けて起動する。

## 復元が `アプリが DB に接続しています` で失敗する

原因：どれかのアプリサーバーで、アプリが動いたまま `db-restore` を実行した。

解決：すべてのアプリサーバーでアプリを止めてから復元する（「[DB バックアップからの復元方法](backup.md#db-バックアップからの復元方法)」）。データは元のまま残っている。

## log-cleaner のログに `warning` が出る

原因：ログ用サーバーで、ログの合計が上限を超えた。

- `app-*` が `LOG_APP_MAX_TOTAL_SIZE_MB` を超え、保存日数より前に古いログを削除した。
- `audit-*` が `LOG_AUDIT_WARN_TOTAL_SIZE_MB` を超えた（監査ログは削除しない）。

解決：ディスクの空きを確認し、必要ならディスクを増やすか、保存日数や上限を見直す（「[古いログの自動削除](log-server.md#古いログの自動削除)」）。
