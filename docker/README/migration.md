# マイグレーション

[目次](index.md)

DB スキーマの変更（マイグレーション）を本番の DB に適用する。
アプリはマイグレーションに関わらない。起動時に DB スキーマのバージョンを確認するだけで、合わなければ起動しない。

- マイグレーションは、[docker/db/migrations/](../db/migrations/) の SQL ファイル。DB のイメージに入っている。
- DB サーバーで、DB のコンテナの `db-migrate`（[docker/db/bin/db-migrate](../db/bin/db-migrate)）が適用する。
- 適用するのは DB ユーザー `migrator`。DB のコンテナの中からだけ接続でき、パスワードはない（「[DB サーバー](db-server.md)」）。
  アプリサーバーには、スキーマを変更できる資格情報を置かない。
- どこまで適用したかは、DB の `schema_migrations` テーブルに記録される。
- アプリが前提にするバージョンは、[src/lib/schema-version.ts](../../src/lib/schema-version.ts) の `SCHEMA_VERSION`。

## マイグレーションの実行方法

アプリを更新するとき（「[アプリの更新方法](update.md)」の手順の 3）と、本番環境を構築するとき（「[本番環境の構築方法](setup.md#構築の順序)」）に行う。

前提条件：

- すべてのアプリサーバーで、アプリを止めてある。DB スキーマを変更している間や変更した後に、古いアプリが DB を使わないようにするため。
- DB サーバーを、新しいイメージのタグで起動してある（「[アプリの更新方法](update.md)」の手順の 2）。

DB サーバーの `/opt/myapp-db` で行う。

```sh
docker compose --env-file .env exec db db-migrate
```

- 適用するファイルごとに `適用します: 0005_….sql` と出し、最後に `マイグレーションを適用しました: 4 → 5` と出る。適用するものがなければ `適用するマイグレーションはありません: 5` と出る。
  何度実行しても、適用するのはまだ適用していないものだけ。
- 1 つのトランザクションで適用する。失敗したときは、元の DB スキーマのまま残る。
  アプリは起動せず、「[マイグレーションに失敗した](troubleshooting.md#マイグレーションに失敗した)」を参照する。
- 時間制限はかけない。大きなテーブルの変更は、終わるまで待つ。

確認方法：「[適用状況の確認方法](#適用状況の確認方法)」で、最後のバージョンが、出力された適用後のバージョンと同じになっている。
その後にアプリを起動し、`app` が再起動を繰り返さない。

## 適用状況の確認方法

DB サーバーの `/opt/myapp-db` で行う。マイグレーションは適用しない。

```sh
docker compose --env-file .env exec db psql -U app -d app -c "SELECT version, applied_at FROM schema_migrations ORDER BY version"
```

- `version` が、適用したマイグレーションの番号。最後の番号が、DB スキーマのバージョン。
- `applied_at` は、適用した日時（UTC）。
- アプリが起動しないときは、アプリのログの `DB 4、アプリ 5` のような値と見比べる（「[アプリが再起動を繰り返す](troubleshooting.md#アプリが再起動を繰り返す)」）。

## マイグレーションの取り消し方法

マイグレーションは前にだけ進める。適用したマイグレーションを戻す仕組み（down）はない。
アプリは DB スキーマのバージョンが同じでないと起動しないので、マイグレーションの後に、アプリのイメージだけを前のタグに戻すこともできない。

取り消すときは、次のどちらかで行う。

| 方法                                           | データ                         | 手順                                                                                                                        |
| ---------------------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 打ち消すマイグレーションを足したイメージを出す | 残る                           | 打ち消すマイグレーションを足して「[イメージのビルド方法](build.md)」でビルドし、「[アプリの更新方法](update.md)」で反映する |
| 更新の前の DB バックアップから復元する         | バックアップの後の変更は消える | 「[DB バックアップからの復元方法](backup.md#db-バックアップからの復元方法)」で復元し、前のイメージのタグで起動する          |

- 更新の前に DB バックアップを取っておくと、後者を選べる（「[DB バックアップの取得方法](backup.md#db-バックアップの取得方法)」）。
- DB バックアップは DB スキーマとデータを一緒に戻す。データだけを戻す方法はない。
