# sugumi 手動確認表

- 版: 初版
- 正本の所在: 本書は規約 §12.5「手動確認表」の実体であり、**ブラウザでしか確認できない項目の
  正本**である。§12.4 の機械検査と対になる（規約 §11.6）。
- 対象と番号の出自: 規約 §12.5 の `M1`〜`M9` と、規約「付録B: 実測すべき事項と実測結果」の
  13件（2026-08-10 にフェーズ1の実測が完了済み）を**1つの表に統合**する（重複する正本を作らないため）。
  番号は元の出自（`M*` / `付録B-*`）をそのまま引き継ぎ、本書独自の番号は振らない。
- 確認したら**確認日・確認したブラウザとバージョン・結果**を必ず埋めること（規約 §12.5）。

## 0. この文書の位置づけ

「実ブラウザでの挙動」はすべて本書に集約する（Node に DOM が無いため。規約 §12.3）。
仕様書側が「機械検査できない」とした項目のうち、ブラウザ起因のものも本書へ送る
（正本を1つに保ち、リリース前の確認を1ファイルで完結させるため。規約 §12.5）。

**未実装の対策を実装済みとして数えるのは、規約文書として最も危険な状態である**（規約 §12.5）。
本表の「結果」欄が空欄の項目は、**まだ何も確認されていない**ものとして扱うこと。

## 1. 統合の方針（重複防止・出自の整理）

規約は2つの実測系列を持つ。

1. **§12.5 の `M1`〜`M9`**: フェーズ1以降で追記していく手動確認の対象。
2. **付録B の13件（番号1〜13）**: フェーズ1で実測が完了した事項（2026-08-10 に全件確定）。
   うち大半はコマンド出力を記録する形の実測であり、一部だけがブラウザの実機を要する。
   **ブラウザ関連の項目は、確定後もブラウザ更新による退行がありうるため、リリース前の回帰確認として
   本表に残す。**

規約は次の2件について、付録B から他所への**扱いの変更**を明記している（重複を作らないための裁定）。

- **付録B-4**（Blink の shadow 内 `<style>` 共有最適化の有無）: 外部から観測する手段が無く、
  合否を持たない判断材料であるため、**付録B に残置**し、本表には統合しない
  （規約が「【付録B に残置・フェーズ1の完了条件に含めない】」と明記）。
  参考として本書1章にのみ記載し、番号としては起こさない。
- **付録B-12**（region ごと差し替わる `aria-live` 領域の読み上げ発火）: スクリーンリーダーの実機が要り、
  Node からもヘッドレスブラウザからも観測できないため、**§12.5-M6 へ移送済み**であり、
  規約の付録Bでは「移送の記録として番号だけを残す」扱いになっている。
  したがって本表では **M6 の1行として統合し、付録B-12 という行は別途起こさない**
  （M6 の「出自」列に付録B-12 からの移送である旨を記す）。

上記2件を除く、付録B の**11件**（1・2・3・5・6・7・8・9・10・11・13）と、§12.5 の **M1〜M9** を
2章の単一表に統合する（合計 20 行）。

## 4. 運用ルール

- **M1（＝付録B-11 と同一の実測）は最優先の確認項目である。** 規約 §9.1 の `script-src` は
  2026-08-10 の実測（付録A F27）と利用者裁定により**既に確定記述**であり、M1 は
  「確定した構成が壊れていないこと」をリリース前に確かめる**退行確認**の位置づけである
  （規約 §12.5-M1）。CSP 違反は画面にもサーバーログにも出ず、§12.4 の Node だけの検査も
  通過してしまうため、確認を怠ったまま進むと退行に誰も気づかない。**M1 が失敗した場合に限り、
  規約 §9.1 の改訂と ADR 起票（`0006-*`）の契機とする**（規約 §11.6）。
- 確認は**確認日・確認したブラウザとバージョン・結果**の3点を必ず埋めてから完了とする。
  空欄のまま「確認済み」として扱わないこと。
- 本表に無い項目を追記する場合は、`#` 列に出自（`M10` または既存の付録B番号の続き）を明記し、
  規約側の該当箇所と対応させること。**正本を分割しない**（本表が統合先であることを崩さない）。
