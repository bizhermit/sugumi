# 0005. 整形ツールに `@biomejs/biome` を採用（統合ツールチェーンを採らない理由を含む）

## 状況

整形（フォーマット）は機械検査できる典型的な作業であるにもかかわらず、devDependencies が
`typescript` / `@types/node` の2つに限られており、Prettier も ESLint も使えなかった（§1.1 X8）。
これは §0.4「レビュー依存の規約は腐る」の唯一の例外を放置している状態であり、整形規約をどう機械的に
担保するかが未決事項として残っていた。利用者から「Vite+ を開発ツールとして許容してよいか」という
提案があり、これを契機に整形ツールの採否を評価した（strat-tech による評価。§0.4 対象）。

## 決定

**`@biomejs/biome` を devDependencies に追加する**（devDependencies は `typescript` /
`@types/node` / `@biomejs/biome` の3つになる。§10.7・§11.7）。**Vite+ 全体の導入は見送る。**

- 値の正本は `biome.json`（整形規則）と `.editorconfig`（インデント・改行・文字コード・末尾空白・
  末尾改行）の2ファイルとし、本書には整形規則を列挙しない。`biome.json` 側で
  `formatter.useEditorconfig: true` を有効にして `.editorconfig` に追従させる（実測: 既定では
  `.editorconfig` を見ないが、有効化で追従することを確認済み）。
- `package.json` の `scripts` に `format`（書き換え）と `format:check`（検査のみ）を置き、CI では
  `format:check` を実行する。
- lint は当面入れない（`tests/architecture.test.ts` が既にプロジェクト固有の検査を持つため）。
- バージョンは厳密固定とし、更新は ADR または PR で明示的に行う。

**§1.1 の3条件（成果物に入らない／ビルドに参加しない／1コミットで外せる）を今回の判定基準として
採用**し、devDependencies 許容基準を旧基準「実行時コードを1バイトも含まない」から改訂した（0001 参照）。

## 理由

**実測（2026-08-10・Node v26.5.0 / npm 11.17.0・`npm install --dry-run --ignore-scripts`）**

| パッケージ | version | 導入パッケージ数 | 備考 |
|---|---|---|---|
| `vite-plus` | 0.2.8 | **86** | Vitest 一式・oxlint・oxfmt・`@voidzero-dev/vite-plus-core` ほか |
| `@biomejs/biome` | 2.5.7 | **2** | 本体＋プラットフォームバイナリ1つ。安定版 |
| `oxfmt` | 0.62.0 | 3 | 本体＋`tinypool`＋バイナリ1つ。**beta（pre-1.0）** |
| `oxlint` | 1.77.0 | 2 | 本体＋バイナリ1つ |
| `dprint` | 0.55.2 | 2 | wasm プラグインを設定ファイルの URL から取得する設計 |

- `@biomejs/biome` はライフサイクルスクリプトを持たず、プラットフォーム別バイナリを
  `optionalDependencies` で配布する（`--ignore-scripts` 下でも正常動作を確認済み。§11.6 の
  `.npmrc` 設定と衝突しない）。
- **テンプレートリテラル内の HTML 文字列を書き換えないことを実物で確認した**（`` `<div   class="x">` ``
  の内側の空白がそのまま残る）。§6.1 の HTML 生成規約・§12.4-9/-10 の属性検査（`attrUrl(` 直後・
  二重引用符必須）と競合しない。
- **Vite+ 全体を見送る理由**: 必要なのは整形1つであり、Vite+ はランタイム・パッケージマネージャ・
  バンドラ（Rolldown）・テストランナー（Vitest）まで束ねる「入口の置き換え」である。Rolldown は
  P3（バンドラ不使用）が、Vitest は P10（`node:test` のみ）が名指しで禁じる対象を内包する。
  §1.1 の3条件に照らすと、統合ツールチェーンは条件2（ビルドに参加しない）と条件3（1コミットで
  外せる）の両方で落ちる。
  - 「no frameworks, no runtime dependencies, just the web platform」という本テンプレートの価値は
    「学ぶべきものが Web プラットフォームだけである」点にある。整形ツール単体はこの学習量を1ミリも
    増やさないが、Vite+ は「まず Vite+ を学べ」を追加し、しかも使わないものの方が多いツールチェーンを
    入口に据えることになり、看板と中身が食い違う。
  - `vite-plus@0.2.8` は 2026-03-13 にアルファ公開され、本評価時点で安定版（1.0）に未到達である。
- **`oxfmt` 単体を次点で見送る理由**: Prettier 互換を目指す設計だが、本評価時点で beta（0.62.0＝
  pre-1.0）であり、「陳腐化からの脱却」が動機の本件で 0.x 系に規約を預けるのは早いと判断した。
- **`oxlint` の追加を当面見送る理由**: `tests/architecture.test.ts` が既にプロジェクト固有の検査を
  多数持っており、汎用 lint を上積みしても得るものが小さい一方、検査の正本が2つに割れる副作用の方が
  大きい。
- **`dprint` を見送る理由**: wasm プラグインを設定ファイルに書いた URL から取得・キャッシュする設計で、
  `package-lock.json` で固定できない依存が増える。§11.6 のロックファイル規律と噛み合わない。
- **整形ツールを導入しない案を見送る理由**: `.editorconfig` が担えるのはインデント・改行・文字コード・
  末尾空白までであり、引用符・セミコロン・行幅・末尾カンマは規約文書＋レビューに残ってしまう。これは
  本書自身の §0.4「レビュー依存の規約は腐る」に正面から反する。

## 影響

- devDependencies は `typescript` / `@types/node` / `@biomejs/biome` の3つになる。README・本書の
  数値表記（従来「2つのみ」）はすべて「3つ」へ更新する必要がある（§10.7「実態と異なる看板を掲げない」）。
- `biome.json` と `.editorconfig` をリポジトリ直下に置く資材として追加する（§11.6）。
- CI に `format:check` を追加する（infra-devops へ引き継ぎ）。
- 整形は `tests/architecture.test.ts`（§12.4）には載せない。汎用整形はコマンド1本で足りるため、
  検査の正本を2つに割らない。
- 供給網の扱いは `typescript` と同じ方式（プラットフォームバイナリを `optionalDependencies` で配布）
  であり、`.npmrc` の `ignore-scripts=true` の対象に含める（新しい種類のリスクを持ち込まない）。

## 却下した代替案

- **Vite+ 全体の導入**: バンドラ（P3 違反）とテストランナー（P10 違反）を内包し、§1.1 の3条件のうち
  条件2・3の両方で落ちるため却下した。86パッケージという規模も、整形1つを得るための取引として
  過大と判断した。
- **`oxfmt` 単体**: Prettier 互換を目指すが本評価時点で beta（pre-1.0）であり、安定版への到達を待つ
  方針とし今回は採用を見送った。
- **`oxlint` の追加**: 既存のプロジェクト固有検査（`tests/architecture.test.ts`）で大部分をカバー
  できており、汎用 lint の追加効果が薄い一方で検査の正本が割れる副作用が大きいため見送った。
- **`dprint`**: wasm プラグインの URL 取得方式が `package-lock.json` によるロックと相性が悪いため
  却下した。
- **整形ツールを導入せず `.editorconfig` と規約文書のみで運用する**: レビュー依存の規約になり、
  §0.4 に反するため却下した。
